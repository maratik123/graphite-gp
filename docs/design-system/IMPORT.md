## Status in this repo: canonical visual base (native Rust GUI target)

This design system is adopted as the **canonical visual language** for graphite-gp's
rendering + UX (`gp-render`, design-doc block 2 / §4). The rendering backend is a
**native Rust GUI** (see [`ai-docs/context.md`](../../ai-docs/context.md)).

These files are therefore a **visual specification / reference**, not compiled or run
in this project. When rendering is implemented (via `/task`):

- `tokens/*.css` → Rust color / spacing / type / effect **consts** (module-level
  `SCREAMING_SNAKE_CASE`, per code-style). `colors.css` is the palette source of truth.
- `components/**` (`.prompt.md` spec + `.d.ts` API + `.jsx` impl) → Rust **widgets**.
  The game-specific set — `MovePad`, `Telemetry`, `CarChip`, `LapMeter` — maps onto
  the HUD/controls the game needs.
- `ui_kits/game/**` → **screen-layout reference** for Setup → Track lab → Race → Results.
- `guidelines/*.card.html` → rendered **specimens** of color / type / spacing / brand.

## Substitutions (flagged by the source; carry forward or replace)

- **Fonts:** Onest (display/UI) + JetBrains Mono (telemetry), via Google Fonts.
  No fonts ship with the source — swap for licensed faces if adopted. (The 2026-07-18
  refresh reconciled the source from Space Grotesk → Onest, matching the repo's #73
  swap; the vendored Rust faces already ship Onest.)
- **Icons:** Lucide (CDN). No icon set in the source. Native marks are geometric
  (point/car, velocity vector, wall, S/F, move pad). No emoji.
- **Logo:** none — the wordmark is plain type (**GRAPHITE GP**).

## Not imported (build artifacts & mid-design assets)

Several files from the source project are intentionally **not** copied here — they are
derived or transient, add no reference value for the native-Rust target, and would only
be regenerated by the design app:

- `_ds_bundle.js` — the compiled component bundle (concatenation of `components/**`
  used by the browser preview pane).
- `_ds_manifest.json` — the generated card/component/token index.
- `_adherence.oxlintrc.json` — the generated lint config enforcing token/prop usage
  in the JSX (the same prop contracts are captured in each component's `.d.ts`).
- `.thumbnail`, `thumbnail.html` — the design app's generated project-thumbnail asset
  and its preview page (neither renders standalone without `_ds_bundle.js`).
- `screenshots/*.png` — mid-design snapshots, not a stable reference.

The **hand-authored build scaffold** *is* carried (added in the 2026-07-18 refresh):
`BUILD.md`, `package.json`, `entry.js` — a standard esbuild setup that rebuilds an
equivalent `ds_bundle.js` from `entry.js`, independent of the design app's generated
`_ds_bundle.js`. These are tooling/reference, not run in this repo.

Because `_ds_bundle.js` is absent, the `*.card.html` previews and `ui_kits/game/index.html`
will **not** render standalone in a browser — that is expected; they are read here as a
visual/layout reference, not executed (or rebuild the bundle locally per `BUILD.md`). To
pull any excluded file byte-exact (or refresh the whole import), re-run the `claude_design`
import against the project id above.

## Keeping in sync

- **Pull (import):** `DesignSync` `get_file` per path (what produced this directory).
- **Push (export local edits back):** `DesignSync` `finalize_plan` → `write_files`,
  via the `/design-sync` skill — incrementally, one component at a time.
- The `claude_design` MCP is authenticated only in the interactive session (via
  `/design-login`); it is not available to spawned sub-agents or headless runs.
