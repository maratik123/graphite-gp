# Гоночная игра на сетке — Design Doc

Сводка проектных решений с обоснованиями. Документ — справочник-спецификация для остальных чатов проекта. Решения, помеченные **[ОТКРЫТО]**, ещё не финализированы.

Сквозной принцип всего проекта: **точка = центр единичной клетки, стена = дуальное ребро на полусетке.** Из него автоматически следуют «стена никогда не проходит через точку», «машинка не касается стены», вывод стен из коридора и корректность масок легальности. Все четыре блока (генерация, рендер, логика, ИИ) читают геометрию через эту дуальность. Это общий язык, а не отдельный модуль.

---

## 1. Модель трассы

**Дискретизация.** Целые точки = проезжие клетки. Коридор `D` — множество этих точек/клеток. Стенки не задаются вручную — это дуальные рёбра на границе между проезжей и непроезжей клеткой. Поэтому «граница не через точку» и «машинка не касается стены» выполнены by construction.

**Топология.** Замкнутая непересекающаяся трасса ⟺ `D` — **аннулюс** (кольцо): связное полимино с ровно одной дыркой (инфилдом). Дырка обязана содержать ≥1 целую точку — иначе область односвязна и это не кольцо. Голая щель-стенка между двумя рядами точек дырки не создаёт → невалидна.

**4-связность — свойство графа коридора/анализа, НЕ движения машинок.** Машинки движутся хордами (скорость может быть большой и диагональной, напр. `(2,3)`); диагонально по фон-Нейману ограничено только *ускорение* (не разгон обеих осей за ход), а легальность хода = хорда + supercover. 4-связность зафиксирована для метрики ширины, distance-transform, топологических проверок и V=1 liveness. Определяет манхэттенскую метрику и то, считается ли диагональный проскок «в игольное ушко» между двумя стенами проходом. 8-связность (для анализа) отвергнута: диагональные касания углами склеивают коридор через инфилд и дают проходы шириной 1.

**Ширина** = число целых точек в поперечном сечении коридора. Переменная ширина допускается: `w(s) ≥ n` везде.

**Параметры ширины (связаны с числом машинок `m`):**
- `n = ⌈m/2⌉` — глобальный минимум (в узких местах). Это нижняя граница на **комфорт/размещение** («не тесно»), НЕ верхняя граница, форсирующая очередь-обгон [D1(a)]: коллизия-слой не моделирует mid-segment трафик, так что узкие места — позиционные/визуальные, а не traffic-механика.
- Ширина на старт-финише `≥ m` — машинки стартуют, стоя вдоль линии поперёк коридора; их физически негде разместить при меньшем хорде. Раньше это требование было «чтоб не тесно» — теперь оно вынужденное стартовой раскладкой.
- Нормальная ширина = `k` (размер крупной клетки скелета), `k ≥ n`.

**S-шпильки** = пальцы инфилда, вклинивающиеся между двумя рукавами коридора. Минимальный поперечный габарит: два рукава (`≥ n` каждый) + перешеек инфилда (`≥ 1`) = `≥ 2n+1` точек поперёк.

## 2. Генерация трассы

Выбранный подход: **A (крупноблочное кольцо, инфилд-first) + D (локальная доводка)**. Причина: оракул проходимости — самая дорогая проверка; этот путь делает трассу почти-валидной by construction, оставляя оракулу роль сертификатора, а не движка перегенерации.

### Параметры
- `m` — число машинок; `n = ⌈m/2⌉`; `k ≥ n` — крупная клетка = нормальная ширина.
- `V_target` — **design-скорость**: целевой потолок, под который размеряются прямые и разгонная зона (`~V_target²/2`). Вход генерации, известен заранее. **[D3]**
- `V_ceil` — плавающая граница поиска оракула (строительные леса BFS, растёт итеративным углублением, см. §3). НЕ вход геометрии. Путать с `V_target` нельзя: `Vmax_attain` — выход оракула, и если он `< V_target`, значит геометрия срезала скорость — это нормально.
- `L_min` — минимальная длина прямой перед поворотом (сид под run-out).

### Конвейер по фазам

**Ф1 — скелет: крупноблочное кольцо (инфилд-first).** Случайное односвязное полимино `P` (дырка); сгладить границу (убрать 1-клеточные зубцы, чтобы прямые ≥ `L_min`); дилатация Минковского на ≥1 блок → кольцо `= dilate(P) \ P`; расширить выбранные стороны. **Зафиксировать ориентацию обхода (CW/CCW) — это глобальный `race_dir` для всей трассы.** By construction: связно, ровно одна дырка, дырка ≥1.

**Ф2 — растеризация в точки `D`.** Каждая крупная клетка → `k×k` точек. Узкие зоны срезать до `n` (не ниже); широкие — 2 блока (`2k`). Тейпер переходов ширины ≤ ~1 точка на несколько столбцов (резкая ступенька = вогнутая ниша, которую режет supercover).

**Ф3 — старт/финиш + поле.** Выбрать прямой участок (не поворот), ориентировать поперёк коридора (H или V). Утолстить до `≥ m`. `race_dir` = проекция ориентации кольца на касательную к участку. Разгонная зона `≥ ~V_target²/2` точек прямой **вперёд** (по `race_dir`) до первого поворота.

**Развести стартовую сетку и тайминговые ворота [C2].** Это два разных объекта:
- **стартовая сетка** — где стоят машинки: передний ряд + доп. ряды назад по `-race_dir`; все `v=(0,0)`, различны, в `D`.
- **тайминговые ворота (`sf`)** — дуальное ребро полусетки, поставленное **на одно ребро впереди переднего ряда**, так что **все** машинки при `t=0` строго позади ворот.
Тогда «первое форвард-пересечение» однозначно и единообразно для всех рядов, и init счётчика `-1` самосогласован (см. §3). Формулировка «на самой линии» устранена: машинки на целых точках, ворота на полусетке — «на линии» геометрически невозможно.

**Ф4 — статическая валидация.** `D` связно (flood fill, 4-conn); дополнение имеет ровно одну ограниченную компоненту ≥1 точки; ширина `≥ n` везде и `≥ m` на S/F (distance-transform как пре-фильтр + точный подсчёт по поперечным сечениям); пальцы инфилда живы. Провал → назад в Ф2 (локально) или Ф1 (сид).

**Ф5 — оракул проходимости (см. §3).** Дешёвый V=1 liveness каждую итерацию; полный `Vmax`-оракул только на зелёном.

**Ф6 — локальная доводка (D).** Каждая правка = сдвиг границы на одно дуальное ребро, затем только затронутые чеки:
- ширина `< n` → выдвинуть внешнюю стену;
- поворот не тормозится → удлинить предшествующую прямую или расширить угол;
- supercover режет вогнутый угол → снять внутренний зуб;
- рукава сливаются / дырка гибнет → срезать внешнюю стену рукава или подвинуть палец.
Луп до валидности или до бюджета правок → рестарт Ф1 с новым сидом.

**Область переверификации зависит от типа правки [C3]:**
- **Статические чеки (ширина, топология):** add-правки (расширить, удлинить, залить зуб) монотонно безопасны для существования круга (`R`, `B`, `live` только растут — коастить можно всегда) → достаточно локального width-чека. Remove-правки (срезать стену, подвинуть палец) могут порвать связность/дырку → нужен глобальный flood-fill (дёшев).
- **Динамические чеки (run-out) НЕ локальны.** Тормозимость поворота — функция *максимальной достижимой скорости входа*, а та задаётся **всем участком выше по потоку**, не окрестностью правки. Удлинение прямой чинит run-out поворота X, но одновременно *повышает* скорость приезда в X — чек фиксированного радиуса возьмёт устаревшую upstream-достижимость и объявит X починенным, пока он всё ещё нетормозим. Правильная локальность — **speed-sink → speed-sink**: переверифицировать достижимость от ближайшего upstream speed-sink (точка, где все живые состояния уже медленные — шпилька или старт разгонной зоны) вперёд через правку до следующего sink. Не «N клеток вокруг правки». Проще — не выдумывать «локальный динамический оракул»: per-edit гонять дешёвый глобальный V=1 liveness, полный `Vmax`-оракул в конце.

**Ф7 — вывод.** Стенки = дуальные рёбра на границе `D`. Экспортируемые артефакты: `D`, `walls`, `sf`, `race_dir`, **`s_field`** (скалярное поле — источник кадра ИИ и награды `Δs`) и **`centerline`** (кривая только для рендера), плюс метрики из оракула.

### Экспортируемый артефакт трассы
`{ D, walls, sf, race_dir, s_field, centerline, Vmax, tempo, fastest_lap, speed_heatmap }`.

**Два разных «центра» — не путать [D2]:**
- **Medial axis** (гребень distance-transform) — ветвящийся геометрический объект, про *ширину*. Живёт в Ф4, параметризации не требует. Это снимает кажущуюся цикличность Ф4→Ф7: Ф4 использует DT/medial axis, а не `s`-параметризованную осевую.
- **`s`-поле** — скалярное поле на `D`, источник кадра ИИ (`t̂=∇s` → `v_tangent/v_normal`, боковые дистанции) и награды (`Δs`). Продукт Ф7.
- **Racing centerline** — одиночная неветвящаяся кривая, **только для идеальной линии рендера** [P2]. ИИ на неё не завязан.

**[P2] Кадр ИИ берётся из градиента `s`-поля, НЕ из рендер-кривой.** Иначе «render-only» кривая перестаёт быть render-only: фичи M1 (`v_tangent`, `v_normal`, `dist_left/right`) требуют касательной/нормали в клетке машинки, и если читать их с кривой — блок 1 обязан блоку 4 качественную параметризованную кривую, а не только поле. Правильно: `t̂ = normalize(∇s)` (определён внутри полосы всегда; у ворот касательная = `race_dir`), `n̂ ⟂ t̂`, боковые дистанции вдоль `±n̂`. Тогда кривая — честно только для рендера, а контракт блок1→блок4 ровно `{ D, walls, sf, race_dir, s_field }`, без кривой. Блок 4 не переизобретает касательную и не привязывается к рендер-сплайну.

**`s` — скалярное поле на `D`, а не проекция на кривую [D2].** Наивный «ближайшая точка на полилинии» складывается на шпильках/широких карманах и портит награду. Определять `s` как граф-дистанцию на **аннулюсе, разрезанном у ворот** (см. N1) — у каждой клетки корректный однозначный монотонный `s` без проекции. Racing centerline как кривая (medial axis → обрезать до петли → ресэмпл по длине дуги → монотонный замкнутый `s`) остаётся для идеальной линии рендера; прогресс `Δs` берётся из поля, не из проекции на кривую. Гарантия: `pos ↦ s` однозначна и монотонна внутри коридора.

**[N1] `s`-поле должно считаться на кольце, РАЗРЕЗАННОМ у ворот — иначе свёртка на антиподе ломает награду.** Ненаправленная BFS-дистанция от ворот по **полному** кольцу не монотонна по `race_dir`: расстояние растёт в обе стороны (CW и CCW) и встречается на **антиподе**. За антиподом движение вперёд по `race_dir` *уменьшает* наивную дистанцию-до-ворот → `Δs < 0` → ложный сигнал «реверс» на всю вторую половину каждого круга. (Разрыв *у самих ворот*, где `s` сбрасывается `L → 0`, ожидаем и нормален — круг ловит счётчик; проблема именно в свёртке на антиподе.) Правильно: `s` = BFS-дистанция на `D \ gate`, засеянная с **передней (`+race_dir`) грани ворот**, с рёбрами ворот как барьерами (пропагация не может обернуться вокруг). Даёт однозначную монотонную координату `0 → L`. То есть `graph_distance_from(sf)` читать как «граф-дистанция на `D \ gate` от передней грани».

**[P1] Уточнение природы фикса N1: это качество сигнала, а не корректность оптимума.** При чистом PBS (C1) оптимальная политика инвариантна к *любому* потенциалу `Φ` (Ng–Harada–Russell), поэтому никакое `s`-поле — свёрнутое или нет — не сдвигает оптимум. Свёртку всё равно надо было чинить, но не потому, что она меняла оптимум, а потому что спайк `Δs ≈ −L` раз в круг — это огромный *вводящий в заблуждение градиент* (дисперсия, нестабильное обучение). Полезный королларий: **мелкие остаточные немонотонности `s`** (небольшой BFS-геодезический дребезг через широкие карманы) **безвредны** — они shaping-only. `s` должно быть **без свёрток, а не идеальным**.

### Верхнеуровневый псевдокод конвейера

Стандартные хелперы считаются данными: BFS/Dijkstra по графу состояний, distance-transform, flood-fill, supercover отрезка, растеризация, дилатация Минковского, сглаживание/сплайн.

```
CONN  = 4                                    # 4-связность: метрика анализа, НЕ движение машинок
MOVES = [(0,0),(+1,0),(-1,0),(0,+1),(0,-1)]  # 5 ускорений фон-Неймана

function generate_track(m, k, L_min, V_target, repair_budget, seed_budget, rng):
    n = ceil(m/2)                            # глобальный минимум ширины
    repeat seed_budget times:                # [N4] бюджет сидов — не бесконечный loop
        skel      = phase1_coarse_ring(k, L_min, rng)       # + фиксирует race_dir (CW/CCW)
        D         = phase2_rasterize(skel, k, n)
        (D,sf,gr) = phase3_start_finish(D, skel, m, V_target)  # ворота впереди сетки [C2]

        repeat repair_budget times:
            issues = phase4_static_checks(D, n, m, sf)         # дёшево: связность, дырка, ширина
            if issues.empty and not oracle_liveness_V1(D, gr, sf, skel.dir):
                issues = [DYNAMICALLY_DISCONNECTED]            # дёшево: V=1 liveness
            if issues.empty:
                res = phase5_full_oracle(D, gr, sf, skel.dir)  # дорого: только на зелёном
                if res.laps_exist:
                    return phase7_output(D, sf, gr, skel, res) # + s_field, centerline, метрики
                issues = res.break_points
            D = phase6_local_repair(D, issues, n, m)           # одно дуальное ребро за правку
            if D == FAILED: break                              # доводка застряла → новый сид
    return GENERATION_FAILED                  # [N4] исчерпан бюджет сидов

# --- Ф1: крупноблочное кольцо, инфилд-first ---
function phase1_coarse_ring(k, L_min, rng):
    P    = random_simply_connected_polyomino(rng)  # [N4] сидированный RNG для реплеев
    P    = smooth_border(P, min_straight=L_min)   # снять 1-клеточные зубцы → место под run-out
    ring = minkowski_dilate(P, 1) \ P             # аннулюс by construction
    widen_selected_sides(ring, rng)
    dir  = choose_orientation(ring)               # CW/CCW → глобальный race_dir
    return { ring, P, dir }

# --- Ф2: растеризация в точки ---
function phase2_rasterize(skel, k, n):
    D = union( k×k точек для каждой крупной клетки skel.ring )
    carve narrow-зоны → ширина n (не ниже);  keep wide-зоны → 2k
    taper переходы ширины ≤ ~1 точка / неск. столбцов   # без вогнутой ниши
    return D

# --- Ф3: старт/финиш; ворота ОТДЕЛЬНО от сетки [C2] ---
function phase3_start_finish(D, skel, m, V_target):
    seg = pick_straight_run(skel.ring)            # не поворот
    thicken(D, seg, width >= m)
    race_dir = skel.dir по касательной к seg
    rows = ceil(m / width(seg))                    # сколько рядов нужно под m машинок
    ensure accel_zone   >= ~V_target²/2 точек ВПЕРЁД по race_dir до первого поворота
    ensure grid_straight >= rows точек НАЗАД по -race_dir в D   # [N4] место под все ряды старта
    grid = стартовая сетка: rows рядов от переднего назад по -race_dir, v=(0,0), различны, в D
    sf   = тайминговые ворота на дуальном ребре, на 1 ребро ВПЕРЁД переднего ряда
    return (D, sf, grid)                          # все машинки строго позади sf при t=0

# --- Ф4: статическая валидация ---
function phase4_static_checks(D, n, m, sf):
    issues = []
    if components(D,CONN) != 1:                      issues += DISCONNECTED
    holes = bounded_components(complement(D),CONN)
    if holes != 1 or size(holes[0]) < 1:            issues += BAD_TOPOLOGY
    for section in cross_sections(D):               # нормаль из скелета
        if width(section) < n:                      issues += NARROW(section)
        if section ∈ sf and width(section) < m:     issues += NARROW_SF(section)
    for finger in infield_fingers(D):
        if absorbed(finger):                        issues += LOST_HAIRPIN(finger)
    return issues

# --- Ф5a: дешёвый liveness, V=1 ---
function oracle_liveness_V1(D, grid, sf, race_dir):   # [N4] race_dir в сигнатуре
    R = forward_reachable(grid@v=0, legal_move within |v|<=1)
    return exists lap-closing S/F-crossing(race_dir) in R

# --- Ф5b: полный оракул + Vmax (итеративное углубление) [D3] ---
function phase5_full_oracle(D, grid, sf, race_dir):   # [N4] race_dir в сигнатуре
    V_ceil = 1
    loop:
        R    = forward_reachable(v=0 starts, legal_move within |v|<=V_ceil)
        B    = backward_reachable(lap-close goal(race_dir), reversed legal_move, |v|<=V_ceil)
        live = R ∩ B
        if no lap in live: return { laps_exist=false, break_points=frontier_gap(R,goal) }  # [N3]
        Vpeak = max|v| over live
        if Vpeak < V_ceil: break                    # граница не связывает → предел геометрии
        V_ceil *= 2
    fastest = shortest_path(live, start → lap-close)
    heatmap = { point → max|v| over live states at point }
    return { laps_exist=true, Vmax=Vpeak,
             tempo=lap_length/len(fastest), fastest, heatmap, break_points=[] }

# --- Ф6: локальная доводка (одно дуальное ребро за правку) ---
function phase6_local_repair(D, issues, n, m):
    for issue in issues:
        match issue:
            NARROW | NARROW_SF        -> push_outer_wall_out(until width >= target)  # add: локальный чек
            NO_BRAKING                -> lengthen_straight() or widen_corner()       # add: sink-to-sink оракул [C3]
            CONCAVE_CHORD_CUT         -> fill_inner_tooth(corner)                     # add: локальный чек
            ARMS_MERGING|LOST_HAIRPIN -> trim_arm_wall() or nudge_finger()           # remove: глобальный flood-fill
            DYNAMICALLY_DISCONNECTED  -> map_frontier_gap_to_edge(issue)              # [N3] крит. шаг, см. ниже
        recheck_by_edit_type()        # add → локально; remove → глобально; run-out → sink-to-sink
    return progressed ? D : FAILED

# --- Ф7: вывод ---
function phase7_output(D, sf, grid, skel, res):
    walls      = dual_edges_on_boundary(D)         # между точками, никогда через точку
    s_field    = bfs_distance(D \ gate_edges(sf),  # [N1] на кольце, РАЗРЕЗАННОМ у ворот
                              seed = forward_face(sf, skel.dir))   # → монотонно 0..L
    centerline = racing_line(medial_axis(D))       # кривая только для рендера [D2]
    return { D, walls, sf, race_dir=skel.dir, grid, s_field, centerline,
             Vmax=res.Vmax, tempo=res.tempo, fastest_lap=res.fastest, speed_heatmap=res.heatmap }
```

Дешёвые чеки (Ф4 + V=1 liveness) крутятся каждую итерацию; дорогой `Vmax`-оракул — только на зелёном и заодно отдаёт метрики скорости. Break-points из него точечно кормят Ф6, поэтому глобальная перегенерация случается лишь при исчерпании бюджета правок.

**[N3] Самый рискованный недоказанный шаг — `frontier_gap → конкретное дуальное ребро` (`map_frontier_gap_to_edge`).** Оракул говорит «достижимость встала здесь», но перевод этого дефицита в *правильное ребро для сдвига* — и есть суть того, сойдётся ли вообще схема «почти-валидно by construction + оракул сертифицирует + локальный ремонт», или она будет часто откатываться в полный reseed. Это единственный шаг, спрятанный за хелпер. Рекомендация: **прототипировать это отображение первым** при старте блока 1 — на руками собранной почти-валидной трассе, до остального конвейера. Именно здесь подход наиболее правдоподобно не сходится.

## 3. Игровая физика (ядро симуляции)

### Движение
Пошагово. Состояние `(x, y, vx, vy)`. На каждом ходу — одно из **5 действий** (ускорение фон-Неймана): `(0,0)`, `(±1,0)`, `(0,±1)`. Новая позиция `(x+vx', y+vy')`. Диагональный разгон за один ход запрещён — это фундамент всех рассуждений про тормозной путь. Старт: все `v=(0,0)`.

### Легальность хода
```
legal_move(D, x,y,vx,vy, (a,b)):
    (vx2,vy2) = (vx+a, vy+b)
    p1 = (x+vx2, y+vy2)
    return p1 ∈ D  AND  supercover((x,y), p1) ⊆ D
```
**Строгий supercover** (все клетки, которых касается отрезок, включая угловые): быстрый хорд не может перепрыгнуть стену и не протискивается сквозь дуальную вершину между двумя стенами. Это runtime-правило И ребро графа оракула — один и тот же код.

**[C4] Точный предикат — самая критичная для корректности деталь; специфицировать целочисленно, без float, юнит-тестить первым в 3a.** `supercover` = множество клеток, чей **замкнутый** единичный квадрат (клетка + её граница) пересекает отрезок; требование `⊆ D`. Ключевой тай-кейс — отрезок через **дуальную вершину** (полуцелую точку `(i+½, j+½)`, общую для 4 клеток): включаются **все 4** клетки, все обязаны быть в `D`. Именно это запрещает проскок «в игольное ушко» между двумя диагонально стоящими стенами. Канонический тест: `(0,0)→(1,1)` проходит через `(½,½)` → требуются `(0,0),(1,0),(0,1),(1,1)` — все четыре. Off-by-one здесь тихо разрешает нелегальные диагональные проскоки ИЛИ запрещает легальные ходы, причём **одинаково ломает и валидацию, и игру** (один код). Таблица кейсов для тестов: осевые, `(1,1)`, `(2,1)` (`gcd=1`), `(2,2)` (`gcd>1`), хорда, задевающая один угол, хорда через две коллинеарные вершины.

### Динамические ограничения трассы (влияют на генерацию)
- **run-out:** перед каждым поворотом прямая `≥ ~v²/2` (тормозной путь для скорости, набираемой на предыдущей прямой). Дискретный аналог «минимального радиуса».
- **разгонная зона** за S/F: `~V_target²/2` для честного старта из покоя.
- **supercover-чистота** у вогнутых углов: быстрый хорд не должен резать внутренний зуб.

### Оракул проходимости
Поиск в пространстве `(x,y,vx,vy)`, 5 переходов, ребро легально по `legal_move`. Трасса валидна ⟺ из старта достижимо замыкание круга через S/F по `race_dir`.

**V=1 — дешёвый liveness.** Sound + complete для бинарного «круг существует» (при 4-связности): ход `(0,0)` всегда доступен, на `v=1` тормозной путь нулевой (разворот почти в любой клетке), supercover не даёт срезок. Стоит почти как flood fill. Но слеп к динамике (run-out, хорд-срезка, шпилька на скорости) — только для liveness-фильтра в Ф6, не как финальный сертификатор.

**Vmax_attain — производная от трассы, а не вход.** `V_ceil` нужен лишь как леса для конечного BFS; истинная достижимая скорость ограничена геометрией (скорость, чей тормозной путь длиннее самой длинной прямой, недостижима на завершаемом круге). `V_ceil` — это плавающая граница поиска, не путать с design-входом `V_target` (см. §2, D3).
- **Живые состояния** = `forward_reachable(старты) ∩ backward_reachable(замыкание круга)`. Состояние с высокой скоростью, из которого не успеть затормозить и финишировать — в `R`, но не в `B` → провабельный краш, отбрасывается.
- **Итеративное углубление:** `V_ceil = 1,2,4,8,…`; как только `max|v|` среди живых `< V_ceil` — это истинный `Vmax_attain` (граница больше не связывает). Финальный BFS может гонять до 2× нужного потолка — незначительная трата, результат корректен.

**Метрики скорости — не путать:**
- **Пиковая** (`Vmax_attain`) — доминируется единственной самой длинной прямой. Плохой скаляр «скоростности».
- **Темп круга** = `длина_круга / число_ходов` быстрейшего пути. Честная «скоростность» (интегрирует прямые и торможения).
- **Хитмап** = для каждой точки max скорость среди живых состояний в ней. Показывает *где* быстро/медленно, диагностирует run-out. Почти бесплатно поверх `R ∩ B`.

### Счётчик кругов
**Знаковый счётчик пересечений** (не позиционный флажок). Пересечение S/F по `race_dir` → `+1`, против → `−1`. Достаточность доказуема: S/F — полный хорд, разрезающий аннулюс в односвязную полосу, поэтому вернуться на линию можно только откатом (декремент гасит инкремент) или полным обходом (настоящий круг). Инициализация `-1` (первый форвард-кросс = старт гонки, не круг); `laps = max(0, counter)`.

Событие фиксируется **по факту пересечения отрезком хода**, ≤1 за ход (две прямые пересекаются раз). Считается **до разрешения коллизий** — телепорт при коллизии/краше счётчик не трогает.

**Полуоткрытый тест пересечения [C2]** — чтобы убить вырождение «конец отрезка ровно на линии»: засчитывать кросс ⟺ `from` строго с `−`-стороны И `to` с `+`-стороны или на линии (интервал полуоткрыт). В связке с разведением сетки и ворот (Ф3, все машинки строго позади ворот при `t=0`) init `-1` самосогласован для всех рядов.

### Валидный финиш
Не отдельное правило — конъюнкция двух существующих: (1) ход легален (`supercover ⊆ D` — ловит вылет в стену после пересечения) И (2) отрезок пересекает S/F по `race_dir`. Порядок: `legal_move` **раньше** проверки ворот. Проверка победы (`counter == нужное`) — по свершившимся пересечениям (шаг 1 тика), не по позиции после коллизий.

### Краш (столкновение со стеной) — ФИНАЛИЗИРОВАНО: гашение с scrub-тиком
Возникает как тупик перебора: все 5 ходов выводят из `D` (вошёл в поворот быстрее, чем позволяет run-out). Реальное событие даже при чистом оракуле.

**Скорость после краша обязана резко упасть** (иначе осцилляция «врезался → откат → врезался»). Обнуление на месте (`v=0`) отвергнуто: это абуз — торможение через столкновение становится доминирующей стратегией (даёт `v=0` мгновенно и бесплатно, дешевле честного торможения в `v` ходов).

**[D4] Абуз — про дешёвое торможение, а не про контролируемый `v=0`.** Гашение касательной `/2` за один тик — это сброс скорости больше, чем даёт честное торможение (`−1`/ход), поэтому «чиркнуть об стену» может быть net-дешевле торможения на высоких входных скоростях. Значит сдерживание — **явная цена**, а не свойство формы скорости.

**Принятое правило:**
1. позиция → последняя валидная клетка вдоль swept-отрезка перед выходом из `D`;
2. скорость: компонента **в стену** → 0, компонента **вдоль стены** → `⌊t/2⌋` (сильное затухание);
3. **scrub-тик:** один ход без права реакселерации;
4. предохранитель: если из respawn-состояния все ходы нелегальны → гасить ещё вдвое, в пределе до `v=0`.

**[N5] Что именно делает краш невыгодным — прогресс и позиция, не кинематика.** Раньше формулировка «scrub-тик делает краш строго хуже торможения на любой скорости» была переусилена: scrub — *константная* цена в один тик, а гашение касательной `/2` — *геометрический* срез скорости. На достаточно высокой входной скорости «чиркнуть об стену (сброс `/2`) + scrub» может выигрывать по числу тиков у линейного торможения `−1`/ход. Настоящее доминирование краша в *гонке* — в том, что он **пиннит прогресс** (`s` не растёт) и **стоит позиции**: `P_crash` (для ИИ) и потеря времени/позиции (для человека) — вот основной анти-абуз рычаг, названный в доке. Scrub-тик и гашение — вспомогательные (гасят осцилляцию и мгновенный контролируемый `v=0`), но не несущие всю нагрузку.

**Нормаль стены [D4]:** = стена, задетая **первой** вдоль swept-отрезка; для угла (две стены сразу) обнулять **обе** конфликтующие компоненты.

**Fallback**, если калибровка `⌊t/2⌋` окажется капризной на практике: вариант 1 — `v=0` в последней валидной клетке + пропуск `P` ходов. Та же анти-абуз-стойкость через временную цену, без неоднозначности направления.

Не финализировано (`P_crash` — основной анти-абуз рычаг для ИИ; для человека — потеря времени/позиции на респавн). Если калибровка затухания окажется капризной — откат к варианту 1 (`v=0` + пропуск `P` ходов): та же анти-абуз-стойкость через временную цену, без неоднозначности направления.

### Коллизия машинок (несколько в одной точке)
Разрешение вне физики движения — отдельный слой. Алгоритм:
1. Шафл машинок внутри группы, шафл групп (сидированный RNG для реплеев).
2. Первая машинка каждой группы остаётся на месте; заносится в occupied **до** смещений (это же покрывает синглтоны = не-коллизии, отсюда универсальность).
3. Для каждой последующей — **ближайшая свободная точка по геодезии внутри `D`** (BFS-наружу, 4-conn). BFS автоматически даёт: расстояние по коридору (не по плоскости), «внутри трассы» (инфилда нет в `D`), «не сквозь стену» (внутри `D` стен нет), равноудалённые = первый слой появления → случайная из них.
4. Occupied обновляется после **каждой** укладки.

Nearest-free выбран вместо «откат на прежнюю позицию»: последняя могла быть занята → каскады/циклы; nearest-free не каскадит (один линейный проход).

**Скорость смещённой машинки — сохраняется** (намеренный `v`), не обнуляется (обнуление вернуло бы абуз «въехать в толпу, чтобы затормозить»). Смещение — телепорт: счётчик кругов не трогается, supercover не проверяется (`q ∈ D` гарантирован BFS). Опционально: ограничить радиус BFS с fallback `v=0` на месте.

**[D1] Swap/pass-through — отдельный чек, а не только same-final-cell.** Текущая модель дедупит только машинки, кончающие ход в одной клетке. Но две машинки могут **обменяться клетками** или **просквозить друг через друга mid-segment** (отрезки ходов пересекаются/меняются местами), и это не отслеживается — они проходят насквозь немоделированно. Это correctness-пробел независимо от дизайна: добавить same-turn проверку, что две машинки не меняются клетками и (в идеале) не threading сквозь друг друга. Этот чек остаётся нужен даже при выбранном (a).

**[N2] Разрешение обнаруженного swap — свернуть в существующий коллизия-слой.** Детекции мало, нужно правило *что происходит*. Принято: трактовать спорное ребро как same-cell конфликт и прогнать через тот же сидированный nearest-free BFS (§ коллизии выше) — один путь разрешения, а не отдельная ветка. Обе машинки как в коллизии: одна остаётся/выигрывает по шафлу, другая смещается на ближайшую свободную; скорость сохраняется, счётчик не трогается.

**[D1] Occupancy — решено: (a) узкие места позиционные/визуальные.** Полноценная occupancy-механика (нельзя кончить/пройти сквозь клетку занятой неуступающей машинкой) НЕ вводится — обгон остаётся чисто позиционным, `n=⌈m/2⌉` обосновывается комфортом, не «комнатой для обгона» (§1). Swap/pass-through чек выше — единственная обязательная правка коллизий; traffic-физика не добавляется.

### Разделение на подблоки
- **3a — чистое ядро:** `step`, `legal_move`, краш, коллизии, счётчик. Детерминированное (при фикс. сиде), без I/O. **Разделяемая зависимость рендера и обучения ИИ.**
- **3b — игровой цикл:** ввод игрока, тайминги, оркестрация, UX.

Обособление 3a — техническая гарантия «боты играют в ту же игру»: тренировка (тысячи сред без рендера) и живая игра используют дословно один код физики.

## 4. Рендеринг + UX

Переиспользует дуальность: асфальт выводится из `D`, не рисуется отдельно.

**Слои (сзади вперёд):**
1. Три области: outfield (фон), infield (дырка — отдельным цветом, чтобы петля читалась), asphalt (объединение единичных клеток по точкам `D`).
2. Стены = граница объединения клеток (уже на полусетке) = `walls`. Штриховать границу заливки или рисовать рёбра — эквивалентно. Никогда не через точку by construction.
3. S/F выделенным цветом/пунктиром.
4. «Тетрадный лист»: линии решётки (светло) + точки. Опционально.
5. Оверлеи-аналитика: раскраска по `speed_heatmap`, `fastest_lap` как линия.
6. Машинки — точки.

**Специфика модели:**
- Стены не считаются заново — граница заливки `D`.
- **Косметическое сглаживание** блочных стен (Chaikin/скругление) допустимо только в пределах полуклеточного зазора: не пересекать ни одну точку, не менять множество проезжих клеток. Чистый рендер — логический `D` и оракул не трогаются.
- **[M6] Не скруглять *внутрь* grazeable-клетки.** У вогнутого угла Chaikin-скруглённая стена может визуально «задеть» машинку, которая легально чиркает угол (или наоборот), потому что логический `D`/supercover не тронут. Рассинхрон рендер↔физика: следить, чтобы скругление не заходило в клетку, которую физика считает проезжаемой-чиркаемой.
- Анимация хода — линейное скольжение по отрезку `(x,y)→(x+vx,y+vy)`; supercover уже подтвердил, что он в `D`.
- Идеальная траектория (опц.) = `fastest_lap` через сплайн; валидна by construction, сглаживать свободно, на коллизии не влияет.

## 5. Обучение ИИ

**Принцип: бот оперирует только человеко-доступными данными.** Честный признак = вычислим из локально воспринимаемого состояния (своя скорость, стены вокруг/впереди, соседи). Нечестный = требует глобального поиска (хитмап, оракул). Хитмап — не вход, а то, что сеть выучивает сама из честной геометрии.

### Входные фичи
```
кинематика:  v_tangent, v_normal                        (проекции на кадр средней линии)
поперёк:     dist_left, dist_right (знаковые → симметрия)
вперёд:      curvature @ {d,2d,4d} со знаком, d ∝ v      (видеть поворот заранее)
             free_dist_ahead (непрерывно, не «сколько пересечений»)
             free_dist_ahead / (v²/2)  — «успеваю затормозить» (честный производный)
цель-coast:  dist_left/right в целевой точке
соперники:   k×(вектор_позиции, отн_скорость, ahead/behind по race_dir)
нормировка:  скорость /Vmax, дистанции /ширину и /(v²/2)
```
Ключевой пункт — **зрение вперёд, масштабируемое скоростью** (`~v²/2`): без него сеть физически не может научиться тормозить за поворот, которого не видит. Альтернатива рукодельным скалярам — веер лучей-дальномеров (аналог человеческого зрения глубины); кинематику из лучей не достать, её оставить явно.

**[M1] Якорить «вперёд» к касательной centerline, а не к вектору скорости.** При `v=0` (стартовое состояние *всех* машинок) велосити-хединг вырожден: lookahead `d ∝ v` схлопывается в 0 (слепота ровно на старте), `free_dist_ahead` без направления, `free_dist_ahead/(v²/2)` = `0/0`. «Вперёд» = вдоль касательной centerline (всегда определена), `d` с полом на малом минимуме, деления защищены. Кадр средней линии у нас и так есть — просто «вперёд» означает centerline-вперёд. **Источник касательной — градиент `s`-поля (`t̂ = normalize(∇s)`), не рендер-кривая [P2]** — так кадр ИИ не зависит от рендера, а контракт от блока 1 остаётся `{ D, walls, sf, race_dir, s_field }`.

Соперникам нужна **относительная скорость**, не только позиция (приближающийся и удаляющийся на той же позиции требуют противоположных действий).

### Память
**Не нужна для одиночной динамики** (feedforward, без рекуррентности). Процесс марковский: `(pos, v)` полностью определяет своё будущее; прошлая своя скорость — это своё же прошлое действие, не новая информация.

**[M2] Но чужой intent частично наблюдаем.** Аргумент «памяти не нужно» железобетонен для одноагентной марковости, но *отложенное действие* соперника (собирается тормозить / поворачивать в тебя) не восстановимо из его позиции+скорости. Wheel-to-wheel относительное *ускорение* соперника или стек 2–3 кадров может значить. Стойку «без LSTM» держим, но frame stack рассматриваем как **вероятно нужный для мультиагентной фазы**, а не только как fallback при урезанном лукахеде. LSTM оправдан лишь при более глубокой частичной наблюдаемости, которой мы в остальном избегаем полнотой фич.

### Архитектура
```
вход ~25–40 фич
  → Linear 64 → ReLU
  → Linear 64 → ReLU          (старт 2×64; потолок 3×128 если недотормаживает)
  → Linear 5 → маска legal_move (−inf на нелегальные) → softmax
  → сэмпл(T) / argmax
```
- **5 логитов, не 2 пороговых выхода.** Пороговая схема (величина + относительная ось) отвергнута: неопределённость «ближайшей оси» при `v=0` (стартовое состояние всех машинок!), разрывность на порогах, невозможность нормальной маски и семплирования.
- **Маска до softmax** (`−inf` на логит → честный ноль, корректная нормировка). Fallback на `(0,0)` без маски, если все 5 нелегальны (защита от `softmax(all −inf)`).
- **Температура** = регулятор мастерства: низкая T = сильный ровный пилот, высокая = шумный ошибающийся. Разброс сложности из одной сети.
- Сеть маленькая намеренно: узкое место — данные и награда, не число нейронов; большая сеть переобучается под геометрию тренировочных трасс (конфликт с целью «боты для любой трассы»). Инвариантность вынесена в фичи (кадр ср. линии, нормировки, зеркальная симметрия), сеть может быть скромной.

### Награда
Структура: плотный shaping + разреженный терминал. Ловушка — жадное потиковое максимизирование прокси должно совпадать с «выиграть гонку».
```
r_tick =  w_prog · (γ·Φ(s') − Φ(s))  # чистый PBS, Φ = s_normalized; знаковый, телескопичный
        − c_time                     # маленький штраф за тик → едь быстро
        − (crash ? P_crash : 0)      # чуть дороже честного торможения
r_terminal = B_lap · laps_completed  # якорь к настоящей цели (знаковый счётчик)
           + B_rank(finish_position) # соревновательность → обгон/защита
```
- **Чистый PBS вместо ratchet [C1].** Раньше здесь было противоречие: прогресс задавался и как «только за новый максимум `s`» (ratchet), и как potential-based shaping (`γΦ(s')−Φ(s)`, `Φ=s`). Это разные механизмы, оба держаться не могут. Чистый PBS с `Φ=s` провабельно оптимум-инвариантен (Ng–Harada–Russell) и **сам гасит реверс-фарм**: движение назад даёт отрицательный shaping, экскурсия «вперёд-назад» телескопится в ≈0 → ratchet избыточен. Ratchet же (клиппинг на 0, не телескопичен) — НЕ форма `γΦ(s')−Φ(s)`, не сохраняет оптимум и может сместить политику к «максимизируй дистанцию» вместо «выиграй». Берём чистый PBS; отслеживать per-episode максимум `s` больше не нужно.
- Прогресс вдоль осевой (`Δs`), **не сырая скорость** (скорость ведёт в стену).
- **НЕ вводить:** штраф за близость к стене (убивает апексы — оптимальная линия режет впритирку), награду за сырую скорость.
- `P_crash` — чуть больше потерянного прогресса от честного торможения: рисковать невыгодно, но не паралич.
- Терминал весомый относительно накопленного плотного (иначе бот «красиво едет», а не «выигрывает»). Стартовать с терминала, явно доминирующего накопленный плотный за круг.
- Критерий доверия члену награды: выразим ли он как potential-based shaping (`γΦ(s')−Φ(s)`)? Если да — оптимум не смещается. Если нет — потенциальный источник вырожденного поведения.
- Нормировка на длину круга (трассо-инвариантность → защита от переобучения).

**Порядок настройки покомпонентно:** сначала `w_prog` + `c_time` (едет и быстро?), потом `P_crash` (рискует, но не таранит и не трусит?), в конце `B_lap`/`B_rank` (гоняется за позицию?).

**Curriculum:** сначала одиночный бот на прогресс+время (научить *ехать*), потом соперники + позиционная награда (научить *гоняться*). Мультиагентный старт с нуля не сходится.

### Вычисления
**CPU, многопоточно по средам — не GPU.** Узкое место — симуляция (сбор фич, маска, шаг), а она последовательна и ветвиста (плохо для GPU). Сеть `2×64…3×128` крошечная; перенос CPU↔GPU на каждый тик съедает выигрыш. Рычаг — `N` параллельных гонок на `N` ядрах (эмбарассингли параллельно). Батч-инференс: собрать фичи со всех сред → один форвард `N×40` → раздать. GPU оправдан только при очень большом батче И крупной сети одновременно. **Профилировать** долю времени симуляция/сеть перед любым переносом. Быстрая целочисленная симуляция (Rust) → больше эпизодов/сек — а число эпизодов, не FLOPs сети, реальная валюта обучения.

**[M3] Детерминизм реплеев vs float-фичи.** Ядро 3a целочисленное и бит-детерминированное, RNG коллизий сидирован — но действия ботов зависят от `f32`-фич, которые не гарантированно идентичны между платформами/компиляторами. Реплей с ботами может разойтись даже при фикс-сиде. Либо считать фичи в фикс-поинте, либо хранить в реплее действия ботов (не только сид).

### Дизайн ботов (сверх обучения)
Скука идеальной траектории = детерминизм + отсутствие реакции + бесконфликтность. Лечение: реактивный выбор хода каждый тик (не заранее проложенный путь), профили (целевой темп, агрессия), управляемое несовершенство (семплирование, поздний тормоз). Сложность регулируется силой контроллера (горизонт, точность, шум), **не читерством** (не давать больше ускорения/иммунитет к стенам). Боты ходят теми же `legal_move`/краш/коллизия-слоями, что и игрок.

## 6. Архитектура: 4 блока

```
        [1 Генерация] ──D, walls, sf, race_dir, s_field──▶ [3a Ядро]
                          └──── D, walls, sf, centerline ──▶ [2 Рендер] ◀── состояние ── [3a]
                                     (centerline = идеальная линия, только рендер)          ▲
        [3a Ядро] ──legal_move, краш, коллизии, счётчик──▶ [4 ИИ] ──action──────────────────┘
                     (тот же движок, другой выбор хода; кадр ИИ из ∇s_field)
```

**Расщепление блока 3** на `3a` (чистое ядро-библиотека) и `3b` (игровой цикл) — ключевое уточнение. 3a — разделяемая зависимость рендера и обучения; без обособления неизбежен второй, расходящийся движок физики.

**Порядок работ:** `3a → (1 ∥ 2) → 4`.
- 3a первым — фундамент всех. Для разработки достаточно одной ручной тестовой трассы, генератор не нужен.
- 1 и 3a почти независимы (стык — формат артефакта трассы), можно параллельно.
- 2 после того, как 3a даёт состояние; требует минимальный артефакт от 1.
- 4 последним по коду, но **фичи/награду проектировать рано** — они накладывают требования назад: `s_field` на блок 1 (кадр ИИ = `∇s`, награда `Δs`; не рендер-кривая, см. P2), доступ к состоянию и маске на 3a. (Уже спроектированы в этом документе.)

**Сквозной failure mode генерации (по валидности):** возмущение либо сливает коридор через инфилд (теряется дырка), либо пережимает ширину `< n`, либо создаёт непроезжаемый угол. Первые два ловит Ф4, третий — Ф5, все три чинит Ф6 без глобальной перегенерации.

**[M7] Это про валидность, не про качество.** Три варианта исчерпывают провалы *валидности*, но не провалы *качества*: трасса проезжаема, но скучна (единственная жизнеспособная линия; или единственный завершающий круг тривиален). Это метрические проблемы, не валидность — их Ф4/Ф5 не ловят, и решаются они метриками темпа/разнообразия, а не топологией.

## Решённые (были открытыми)

- **Краш-правило — РЕШЕНО [D4]:** гашение с сохранением направления (нормаль→0, касательная→`⌊t/2⌋`) + scrub-тик без реакселерации + fail-safe до `v=0`. Fallback — вариант 1. См. §3.
- **Occupancy-механика — РЕШЕНО (a) [D1]:** узкие места позиционные/визуальные; traffic-физика не вводится; `⌈m/2⌉` обосновывается комфортом. Swap/pass-through чек — обязательный correctness-фикс независимо от этого. См. §3, коллизии.

## Открытые вопросы

- **Детали профиля ширины** — конкретные пороги тейпера. Рекомендация: держать `k` везде, кроме назначенных «технических» секций; только там сужать к `⌈m/2⌉`. Инвариант: вогнутый *шаг* ширины ≤1 точка, тейпер растянут на ≥ несколько столбцов, пост-чек что ни один вогнутый угол не режется supercover на правдоподобных скоростях входа.
- **Конкретные веса награды** (`w_prog`, `c_time`, `P_crash`, `B_lap`, `B_rank`) — подбор эмпирический, порядок настройки задан. `P_crash` — чуть выше прогресса, теряемого честным торможением с типичной скорости входа в поворот.

## Порядок применения правок ревью (по приоритету)

1. **C4** — точная спека supercover + тесты. Фундамент, блокирует всё 3a.
2. **C1** — чистый PBS. Дёшево, убирает реальное противоречие до любого RL.
3. **C2** — развести тайминговые ворота и стартовую сетку. Дёшево, гасит off-by-one в счётчике и Ф3.
4. **D2** — построение racing centerline + отделение от medial axis. Разблокирует фичи ИИ, награду, ширину Ф4.
5. **D1** — swap/pass-through чек (correctness) + решение по occupancy (design).
6. **C3 / D3 / D4** и рекомендации открытых вопросов — по мере выхода соответствующих блоков.
7. **[раунд 2] N1** — `s`-поле на разрезанном кольце (качество сигнала, блокирует награду). **N3** — прототипировать `frontier_gap → ребро` первым в блоке 1. N2/N4/N5 — по мере выхода.

**Статус:** раунд 1 (C1–C4, D1–D4, M1–M7) внесён; краш-правило (D4→scrub) и occupancy (D1→a) финализированы. Раунд 2 (N1–N5) внесён: N1 (`s`-поле разрезом у ворот) — фикс качества сигнала (не сдвиг оптимума, см. Раунд 3 — **сошёлся**: P1 (природа фикса N1 + королларий «`s` без свёрток, а не идеальное») и P2 (кадр ИИ из `∇s`, кривая — только рендер, контракт блок1→блок4 = `{D, walls, sf, race_dir, s_field}`) внесены. Раунд 4 — **P3** (косметика): диаграмма §6 и work-order приведены к пост-P2 контракту — `s_field` на ребро к ядру/ИИ, `centerline` на ребро к рендеру.
