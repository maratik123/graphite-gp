## Status (2026-07-18)

- Design: **finalized** (`docs/design.md`), reviewed across 4 rounds.
- Code: **scaffold + geom physics primitives** — module structure, `TrackArtifact` type, and stub APIs in place. `crates/core/src/geom/` (split into `mod.rs` + a private `graph.rs`) implements the exact integer `supercover` predicate (full §3 C4 test table) plus the corridor-graph helpers: 4-conn `flood_fill` / `component_count`, `bounded_complement_components` (the §2 Ф4 infield-hole test), in-`D` geodesic BFS (`CorridorScratch::geodesic_bfs` reusable-scratch visitor + eager `geodesic_layers`), and `walls_from_boundary` (Ф7 dual edges). The box/index math is factored into `Size { width, height }` (unsigned) + `Rect { origin, size }` value types; `Corridor` is `{ rect, cells }` with **unsigned** dimensions — negative dims are unrepresentable, so `Corridor::new` needs no `assert!` and **gp-core has zero production panics** (`Rect::index` is total via `checked_sub` + `usize::try_from`). Every integer op is now **overflow- and signedness-safe by construction** (issue #48): `Point::neighbors4` saturates, `legal_move` / `walls_from_boundary` use `checked_add`, and each deliberately-retained bounded raw op carries a documented domain bound + covering test. `Wall` is `{ cell, side: Side }` (4-way outward `Side`). `legal_mask` returns a typed `enumflags2::BitFlags<Action>` set (re-exported from `gp-core::sim` so consumers need no direct `enumflags2` dep) rather than a positional `[bool; 5]` — issue #51. The **`TrackArtifact` contract is now finalized** (issue #6): `SField` distance/gradient/tangent accessors (`t̂ = normalize(∇s)`, gate cells → `race_dir`, gradient barred at the gate cut), `StartGrid` (distinct `v=(0,0)` positions, front-to-back along `−race_dir`), the `TimingGate` half-grid segment on `StartFinish` (`separates` barrier + explicit `forward: Side`), and `Centerline::at` arc-length sampling (wrap-around + total, no panic) — contract types + read accessors on hand-filled fixtures; the block-1 generator that populates them stays `todo!`. `sim::step` — the pure accelerate-then-advance state advance (`(vx',vy') = v + accel`, then `pos += (vx',vy')`) — is implemented as an infallible `const fn` on the assumed-legal domain (no legality check; that stays `legal_move`'s sole job), joining the already-live `legal_move` / `legal_mask` path (issue #7). `LapCounter::register_move` — the signed **half-open S/F crossing test** over the half-grid timing gate (`+1` forward / `−1` reverse, ≤1 event/move via a doubled integer perpendicular coordinate whose odd `GATE_LINE` value is unreachable by real `Point`s), with the `legal_move`-first valid-finish conjunction expressed at the call site — is implemented (issue #8). `sim::resolve_crash` — the finalized **quench-with-scrub crash rule** (a search dead-end where `legal_mask` is empty): respawn at the last swept cell still in `D` (a projection-ordered `supercover` walk, no second geometry path), zero the into-wall velocity component and damp the along-wall component to `⌊t/2⌋` (a concave corner zeros both), plus a one-tick forced-`Coast` **scrub** marker and a whole-vector-halving **fail-safe** (guarded by an `L∈D` termination check; inherits `supercover`'s bounded-chord precondition) that never yields a penalty-free controlled `v=0` — is implemented as a pure `resolve_crash(d, s) -> CrashOutcome` whose `action_mask` / (total) `consume_scrub` make the scrub tick unit-testable inside `gp-core` (issue #9). `sim::resolve_collisions` — the **same-final-cell collision resolver** (issues #10 + #49): cars ending a turn on the same cell are bucketed, a seeded `rand_chacha` ChaCha8 RNG (canonical `sort_unstable_by_key(|g| g[0])` order → `groups.shuffle` → per-group shuffle → `u32` equidistant tie-draw, cross-arch-reproducible) picks the winner + displacement order, and each loser teleports to the nearest free cell via the in-`D` geodesic BFS (velocity retained, no supercover/lap-counter touch, single occupied-after-each pass). Per a **product-owner amendment (2026-07-16)** the predicate is same-final-cell **only** — the swap/pass-through detector (`docs/design.md` [D1]/[N2]) was dropped, so swaps / mid-segment / orthogonal crossings ending on **distinct** cells are allowed, and the two canonical docs were corrected to match. The tie-draw is total (`u32::try_from(..).unwrap_or(u32::MAX)`) so **gp-core keeps zero production panics**. A follow-up **PR #68 review amendment** changed `resolve_collisions` to take a **caller-owned physics RNG handle** (`rng: &mut ChaCha8Rng`, drawn from but never re-seeded) rather than a per-call `seed: u64`, establishing a **per-domain seeded-RNG architecture** — one long-lived stream each for physics / track generation / AI learning / AI inference (the AI streams and the block-3b game-loop stream ownership are deferred). Issue #49 also adds the `rand` + `rand_chacha` (`0.10`, `default-features = false` ⇒ no `getrandom`/OS entropy) stack to **both** `gp-core` and `gp-gen`, with a seeded `GenParams::rng() -> ChaCha8Rng` (gp-gen's generator stochastic usage stayed deferred at the time — #49's remainder, **since closed by the Ф1 PR below**). **97 gp-core + 2 gp-gen unit tests** (as of that PR). The `gen` / `render` / `ai` algorithms are still `todo!()` (marked `TODO(<block>)`). Whole workspace builds clean.

Fixing the face removed the *reason* egui's bundled fallbacks were load-bearing, so `default_fonts` went off in the same task: **−1,443,320 B (1.376 MiB) measured** (25,488,456 → 24,045,136), within 1.19% of prediction. - **Onest swap + `default_fonts` off (block 2, #73):** the font stack is now **Onest + JetBrains Mono and nothing else** — egui's four bundled faces (Ubuntu-Light, Hack, NotoEmoji, emoji-icon-font; 1,414,020 B) are gone, via the **feature flag only** (`epaint_default_fonts` is an optional crate gated by `epaint/default_fonts`; removing map entries at runtime would not shrink the binary). Five things here are load-bearing and none of them look it:
  - **Empty family ≠ missing family.** `FontDefinitions::empty()` binds exactly two keys (`Proportional`/`Monospace` → `vec![]`); a `FontFamily::Name(..)` is bound **not at all**. Empty → `GlyphInfo::INVISIBLE` (**silent**); missing → `panic!` (`epaint fonts.rs:1027-1031`) (**loud**). Two paths ~380 lines apart in one file with **opposite** failure modes — a design doc conflated them and shipped a provably-panicking test sequence past one review round.
  - **The wgpu harness goldens' early `return` is the panic defence, not dead code** (e.g. `app_shell_matches_golden` in `app_gallery.rs`; the `*_gallery` screen/widget goldens share the idiom). `egui_kittest`'s `Harness::from_builder` runs the app closure at *build* time against a `None` ctx (`builder.rs:189,239`), so a post-build `set_fonts` is **unreachable**. The test installs fonts *inside* the closure, returns before drawing on frame 1 (a `fonts_installed` latch), draws from frame 2, then `run_steps(1)` — **not** `run()`/`run_ok()`, which loop on repaint requests. Deleting the `return` reproduces `FontFamily::Name(..) is not bound to any fonts`.
  - **`gp-game`'s `winit` dep is never `use`d and must not be deleted.** `"winit/default"` **cannot** be written in a dependent's inline `features` array (slash syntax is legal only inside a crate's *own* `[features]` table — `cargo metadata` rejects it), so the direct dep carries `wayland-dlopen` + `wayland-csd-adwaita` to the single shared winit via feature unification. Deleting it **compiles, passes clippy, and silently** demotes Wayland CSD to `FallbackFrame`. `unused_crate_dependencies` is configured nowhere; **the `Cargo.toml` comment is the only durable guard** (the AC18 probes ran once, at implementation time).
  - **gp-render's two Miri-gate *causes* are distinct, and both now live in `app_gallery.rs`** (the vestigial `placeholder.rs` that once held them was deleted with #23 once its `draw_placeholder` scaffold had zero production callers; the `tessellation_smoke` canary was relocated verbatim, repointed onto `AppShell::show`). A **wgpu golden** (e.g. `app_shell_matches_golden`): FFI/`dlopen`s the Vulkan ICD. `tessellation_smoke`: since it draws text, it hard-panics on `bytemuck::cast_slice_mut::<u8,u32>` in `vello_cpu`'s `copy_solid` (Miri's allocator grants `u8` alignment; native malloc over-aligns) — **not** UB, and **not** the same reason. Copying one justification onto the other would be a false justification. Under Miri, gp-render therefore exercises only its **pure production-logic** tests (`fonts.rs`, the track/widgets `const fn resolve` + geometry layers, the icon CPU-bakes) — its `tokens::*` constant-vs-CSS tests, the `#[cfg(test)]` `tokens::css` parser self-tests, and the `test_util` float-assert self-tests are **all Miri-gated too** (**B.1 / #107**, 2026-07-21): zero-production-UB-signal, cost-not-abort (`~194 s` of interpreted wall-clock, no UB signal — see AGENTS.md § Rust Test Conventions).
  - **`Fonts::has_glyph` is unsound as a coverage oracle** — it is `resolve_face(c) != replacement_face_key`, where the replacement face is the first carrying `◻`, and `◻` U+25FB is absent from **both** vendored faces. Glyph-coverage assertions go through **`skrifa`** (already in-graph as epaint's own dep; free as a dev-dep).

This is **load-bearing, not cosmetic**: `core.autocrlf` set in any contributor's personal `~/.gitconfig` (it is global-only on at least one dev machine, never in-repo) rewrites CRLF endings **at `git add` time**, which silently committed Space Grotesk's `OFL.txt` as 4,402 B instead of its upstream 4,495 B — breaking both the SHA-256 pin and the OFL's redistribution requirement, with no error. ### #31 — gp-gen Ф6: local repair — one dual edge per edit + edit-type-scoped recheck (C3)

**Landed:** 2026-07-24 · branch `feat/2026-07-24-gp-gen-phase6-local-repair` · new modules `coarse.rs`, `phase4_defects.rs`, `phase5_runout.rs`, `phase6_repair.rs`, `phase6_arms.rs`, `phase6_remove.rs` · gp-gen 153 → **229** tests.

`phase6_local_repair(ctx, issues) -> RepairOutcome` is a **single pass**: for each issue, dispatch → derive one dual edge → scratch-apply → run the *edit-type-scoped* recheck → commit iff that arm's own metric strictly improved. `Repaired { d, edits }` iff ≥1 edit committed, else `Failed` (the reseed signal). The repair-budget loop stays with `generate()` (still `todo!`).

**Traps and invariants worth not rediscovering:**

- **A path-indexed `runout_room` makes every run-out add-arm provably vacuous.** AC3 freezes the fastest-lap path (recomputing it would need the full oracle, defeating the sink-to-sink scoping), so a path-step-counted run-out room is *constant* under an edit — while `attainable(c)` is monotone non-decreasing under an add. The deficit can then only grow, so "strictly decreases" is unsatisfiable and both run-out arms dispatch forever without acting. Fixed at design time: `runout_room` is **geometric** (`wall_run(D,c,dir) − 1`, the lever `lengthen_straight` grows) plus a measured `v_corner` (the lever `widen_corner` grows). Generalise the lesson: **check every commit metric can actually improve under its own arm's edit.**
- **`NoBraking` can never be a lappability verdict.** #30's AC7 proof (`live` monotone in `V_ceil`) means the oracle never reports a dynamic-only stall — a driver can always crawl. `NoBraking` is a `v_target`-referenced *run-out budget* check, the per-corner form of §2 Ф3's accel-zone rule.
- **A fixed-radius recheck window is not a state-space cut; a speed sink is.** With no barrier the "radius-N" flood legally backs up and re-accelerates (`W,E,W,E,…` then `E,E,E`), reaching the corner at full speed and collapsing onto the global answer. So `window_speed`'s `barriers` argument is **mandatory and is exactly the seed cells**, and **seed states expand even when their own cell is a barrier** (only *successors* landing on a barrier are recorded-not-expanded) — the detection call's seed cell is itself a sink, so without that exemption its flood is empty. Both directions carry direct regression tests; either is a one-line change a refactor could undo in good faith.
- **`speed_heatmap` is a per-point max over all live states**, so "the sink set is non-empty by construction" is false — a start cell traversed fast on a later lap has heatmap > 1. `sink_indices` unconditionally includes path index 0 (race-start seeds are at rest ⇒ a conservative superset, never a stale window).
- **`fill_inner_tooth` cannot use "tooth count strictly decreases"** — a 3-cell line hole `A–B–C` has leaves `A`,`C`; filling `A` leaves `B–C`, still 2 leaves. The metric is "named tooth became drivable + exactly one bounded complement component survives". The degree-1 guard is a **topology** guard, not an infield-membership guard (deciding infield membership needs the very flood `[C3]` forbids on an add-edit).
- **`widen_corner`'s lever is real but far narrower than it reads.** Because `legal_move` adds the *new* (possibly decelerated) velocity, a single-cell perpendicular add can only rescue a state already dominant on the *perpendicular* axis — never one merely carrying forward speed. A naive "filled box minus one cell" fixture measures exactly zero effect; the discriminating fixture must seed one hop from `end` along the perpendicular axis.
- **`Point`'s derived `Ord` is x-then-y but `box_points` walks row-major** — the two orders disagree, so any detector promising ascending-`Point` emission must sort explicitly rather than inherit `box_points`' incidental order.
- **`Corridor::set` is a no-op outside the fixed bbox** and Ф2 pads by `BBOX_PAD = 1`, so an outward add-edit has at most one cell of headroom; an out-of-box target is *not a candidate* (it would silently do nothing).
- **Ф6 ordering surrogates → derived `Ord` (block 1, #153):** a **behaviour-preserving refactor** (follow-up to #31/PR #152 review) replacing the hand-rolled ordering keys `phase6_repair::{issue_rank, axis_rank, issue_sort_key}` and `phase5b::wall_sort_key` with `#[derive(PartialOrd, Ord)]`. Narrowly relaxes #31's `AC11 = no gp-core change`: `gp-core`'s `Orient`, `Side`, and `Wall` each gain `Ord`+`PartialOrd` (nothing else in `gp-core` changes; verified no `BTreeSet`/`BTreeMap`/`BinaryHeap` keyed by `Wall`/`Side`, so the new order reaches zero existing collections). **`Issue` was reordered to severity order** (`Disconnected < BadTopology < LostHairpin < ArmsMerging < ConcaveChordCut < Narrow < NarrowSf < NoBraking`, #31 Decision 4 ranks 0–7) then derived — the one non-trivial choice (**option (a) reorder-and-derive**, because a hand-written `Ord` would merely relocate `issue_rank`, not delete it); the reorder is workspace-safe because `Issue`'s declaration order is unobserved (no `as`-cast/strum/`EnumIter`/manual `Ord`; gen-internal, `gp-game` never names it). `Side`/`Wall` needed **no** reorder — declaration order (`East<West<North<South`) and field order (`cell` then `side`) already equal the old rank term-for-term, so a plain derive reproduces `wall_sort_key = (cell, side_rank)`. `DispatchLabel` derives `Ord` with `DynamicStall` kept last; the dispatch sort is now `labels.sort()`. Owner-directed spec amendment mid-`/task` pulled `Side`/`Wall`/`wall_sort_key` in from *deferred*. Net: `wall_sort_key` + the three dispatch surrogates deleted (whole-`crates/` grep-clean), determinism/tie-break tests retained and re-targeted onto the derived order, +4 net new tests (gp-core 118→121, gp-gen 231→232 — the other gen test changes are renames, not additions). No change to `phase6_local_repair`'s output on any fixture.

**Landed:** 2026-07-24 · branch `feat/2026-07-24-s-field-bfs-gate-cut` · new production items `Corridor::rect`, `barrier_distance_field` (`geom/graph.rs`), `TimingGate::forward_face` + `SField::from_gate_bfs` (`track.rs`) · gp-core 121 → **140** tests.

- **The barrier stays generic to preserve layering.** `track` depends on `geom`, never the reverse. A `TimingGate`-typed BFS inside `geom` would invert that; keeping `barrier: impl Fn(Point,Point)->bool` in `geom` and doing the `gate.separates` wiring in `track.rs` keeps `geom` free of `track`.

- **Third BFS-shaped loop in `geom`** (with `geodesic_bfs` and `DistanceTransform`'s inline BFS) but three distinct semantics (visitor+scratch; `u32`-0-sentinel wall distance; multi-seed `Option<u32>`+barrier) — below the ≥3-site mechanical-copy consolidation bar; a future 4th variant should trigger a consolidation look.
